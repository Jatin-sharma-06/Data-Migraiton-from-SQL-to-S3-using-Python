Step 1 — SQL Server on RDS

Provision the source database, configure security, and seed test data
1

Create the RDS SQL Server instance

▶

Navigate to RDS → Create database. Select Microsoft SQL Server and choose the Express Edition (free-tier eligible for POC). Recommended settings:

RDS Settings
Engine:          Microsoft SQL Server (Express)
Instance class:  db.t3.small
DB identifier:   raptbot-sql-poc
Master username: admin
Master password: <your-password>
Storage:         20 GiB gp3
Public access:   YES  ← required for DMS + SSMS
VPC:             default (or your DMS VPC)
⚠️Enable Public access for the POC so SSMS and DMS can reach the instance. In production, use VPC peering or a private subnet instead.
2

Configure the security group (port 1433)

▶

Go to EC2 → Security Groups, find the security group attached to your RDS instance, and add an inbound rule:

Inbound Rule
Type:       Custom TCP
Protocol:   TCP
Port range: 1433
Source:     0.0.0.0/0   (or your IP for tighter security)
💡For production, restrict source to the DMS replication instance's IP / security group instead of 0.0.0.0/0.
3

Connect via SSMS & seed test data

▶

Copy the Endpoint URL from your RDS instance page. Open SQL Server Management Studio, choose SQL Server Authentication, and connect:

SSMS Connection
Server name:  <rds-endpoint>,1433
Auth:         SQL Server Authentication
Login:        admin
Password:     <your-password>

Once connected, run the following to create the demo schema:

SQL
-- Create database
CREATE DATABASE poc;
USE poc;

-- Create sales table
CREATE TABLE sales (
    id          INT IDENTITY(1,1) PRIMARY KEY,
    product     NVARCHAR(100),
    quantity    INT,
    amount      DECIMAL(10,2),
    sale_date   DATE,
    region      NVARCHAR(50)
);

-- Insert sample rows
INSERT INTO sales (product, quantity, amount, sale_date, region)
VALUES
  ('Laptop',   5,  54999.00, '2024-01-10', 'North'),
  ('Monitor',  12, 18500.00, '2024-01-15', 'South'),
  ('Keyboard', 30, 2200.00,  '2024-02-01', 'East'),
  ('Mouse',    50, 850.00,   '2024-02-14', 'West');

-- Verify
SELECT * FROM sales;
ℹ️DMS needs the SQL Agent to be enabled for full-load + CDC. For Express Edition (POC), full-load only is supported.
⚙️

Step 2 — DMS Replication Instance

The compute engine that reads from SQL Server and writes to S3
1

Create the replication instance

▶

Go to AWS DMS → Replication instances → Create replication instance:

DMS Replication Instance Settings
Name:               dms-replica
Description:        Raptbot SQL→S3 POC
Instance class:     dms.t3.medium  (sufficient for POC)
Engine version:     latest stable
VPC:                same VPC as your RDS instance
Multi-AZ:           No (single AZ for POC)
Publicly accessible: Yes  ← needed if RDS is public
⚠️The replication instance and RDS instance must be in the same VPC, or you need a VPC peering / transit gateway between them.

Creation takes 5–10 minutes. Wait until the status shows Available before creating endpoints.

🔌

Step 3 — DMS Endpoints

Source (SQL Server) and Target (S3) — with IAM role setup
1

Create source endpoint (SQL Server)

▶

DMS → Endpoints → Create endpoint → Source endpoint

Source Endpoint Config
Endpoint type:       Source
Engine:              Microsoft SQL Server
Endpoint identifier: sql-source-poc
Server name:         <your-rds-endpoint>.rds.amazonaws.com
Port:                1433
SSL mode:            require
Database name:       poc
Username:            admin
Password:            <your-password>

Click Test endpoint connection, select your replication instance, and verify the status shows successful.

1

Create target endpoint (Amazon S3)

▶

First create your S3 bucket (e.g. raptbot-dms-poc in ap-south-1). Then create the endpoint:

Target Endpoint Config
Endpoint type:           Target
Engine:                  Amazon S3
Endpoint identifier:     s3-target-poc
Bucket name:             raptbot-dms-poc
Bucket folder:           poc-migration   (optional prefix)
Service access role ARN: arn:aws:iam::<account-id>:role/dms-s3-access-role

-- Optional: change output format to Parquet
Data format:             CSV   (default) or parquet
Timestamp column name:   _migrated_at   (adds migration timestamp)
💡For Parquet output, add "DataFormat": "parquet" in the Extra connection attributes field, or set it via the UI's Additional settings.
1

Create IAM role for DMS → S3

▶

Go to IAM → Roles → Create role. Select AWS service → DMS as the trusted entity.

Trust Policy (auto-generated by wizard)
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect":    "Allow",
    "Principal": { "Service": "dms.amazonaws.com" },
    "Action":    "sts:AssumeRole"
  }]
}

Attach the following managed policies:

Policies to attach
AmazonS3FullAccess
AmazonDMSRedshiftS3Role  (covers DMS→S3 write perms)
AWSDMSCloudWatchLogsRole (for task logs)

Name the role dms-s3-access-role. Copy its ARN and paste it into the S3 target endpoint's Service access role ARN field.

⚠️If the endpoint test fails with a permissions error, also attach an inline policy granting dms:* on *. Remove after POC — this is overly broad for production.
🚀

Step 4 — Create & Run the Migration Task

Wire up source → replication instance → target and start the load
1

Create the database migration task

▶

DMS → Database migration tasks → Create task

Task Settings
Task identifier:        raptbot-sql-to-s3
Replication instance:   dms-replica
Source endpoint:        sql-source-poc
Target endpoint:        s3-target-poc
Migration type:         Migrate existing data
Start task on create:   ✓ (or start manually)

-- Table mappings (Wizard mode) --
Schema name:  poc
Table name:   %       (wildcard = all tables)
2

Monitor table statistics

▶

Click into the task → Table statistics tab. You'll see each table with status like Load in progress → Load complete. Once all tables are complete, check your S3 bucket:

Expected S3 structure
s3://raptbot-dms-poc/
  └── poc/               ← schema name
       └── sales/         ← table name
            └── LOAD00000001.csv
💡Switch to Parquet in the S3 target endpoint settings and restart the task to get columnar format — much better for Athena queries.
🐍

Step 5 — Python Migration Script

Your existing tool, evolved to speak directly to SQL Server → S3

The new script (sql_to_s3_dms_migration.py) extends your Zendesk uploader into two modes:

Architecture
MODE 1 — Direct Export (no DMS)
──────────────────────────────────────────
SQL Server (RDS)
    │  pyodbc  SELECT *
    ▼
In-memory CSV / Parquet buffer
    │  boto3  s3.put_object()
    ▼
s3://<BUCKET>/<prefix>/<schema>/<table>/<ts>.csv

MODE 2 — DMS Monitor
──────────────────────────────────────────
Existing DMS task (ARN)
    │  boto3  start_replication_task()
    ▼
Polls describe_table_statistics() every 15s
    │
    ▼
Prints per-table progress until Load complete
ℹ️The original Zendesk script used API Gateway + presigned URLs. The new script removes that layer and talks directly to RDS via pyodbc and to S3 via boto3.
bash
# 1. Python deps
pip install boto3 pyodbc pandas pyarrow requests

# 2. ODBC Driver 18 for SQL Server
#    Windows: download from Microsoft
#    Ubuntu/Debian:
curl https://packages.microsoft.com/keys/microsoft.asc | sudo apt-key add -
curl https://packages.microsoft.com/config/ubuntu/22.04/prod.list \
  | sudo tee /etc/apt/sources.list.d/mssql-release.list
sudo apt-get update
sudo ACCEPT_EULA=Y apt-get install -y msodbcsql18

# 3. AWS credentials (choose one)
aws configure                          # interactive setup
# OR set AWS_ACCESS_KEY_ID / AWS_SECRET_ACCESS_KEY env vars
VariableExampleRequired for
SQL_SERVERmydb.xxxx.rds.amazonaws.com,1433export mode
SQL_DATABASEpocexport mode
SQL_USERNAMEadminexport mode
SQL_PASSWORD***export mode
S3_BUCKETraptbot-dms-pocexport mode
AWS_REGIONap-south-1both modes
DMS_TASK_ARNarn:aws:dms:...monitor mode
S3_PREFIXdms-exportoptional
OUTPUT_FORMATcsv or parquetoptional
AWS_PROFILEraptbot-devoptional
bash — Direct export (all tables)
export SQL_SERVER="mydb.xxxx.rds.amazonaws.com,1433"
export SQL_DATABASE="poc"
export SQL_USERNAME="admin"
export SQL_PASSWORD="MySecret123"
export S3_BUCKET="raptbot-dms-poc"
export AWS_REGION="ap-south-1"

python sql_to_s3_dms_migration.py export
bash — Export specific tables, Parquet format
export OUTPUT_FORMAT="parquet"
python sql_to_s3_dms_migration.py export --tables sales customers
bash — Dry run (no upload)
python sql_to_s3_dms_migration.py export --dry-run
bash — Start & monitor a DMS task
export DMS_TASK_ARN="arn:aws:dms:ap-south-1:123456789:task:XXXXX"
export AWS_REGION="ap-south-1"

python sql_to_s3_dms_migration.py monitor --start

Pre-flight Checklist

Tick each item before starting the migration task
  • RDS SQL Server instance is Available
  • Security group allows TCP 1433 inbound
  • SSMS connected & test data inserted in poc.sales
  • DMS replication instance is Available
  • IAM role dms-s3-access-role created with S3 & DMS policies
  • Source endpoint test → successful
  • Target S3 endpoint test → successful
  • S3 bucket raptbot-dms-poc created in ap-south-1
  • DMS migration task created with correct table mappings
  • Task status → Load complete & CSV files visible in S3
  • Python script env vars set & --dry-run tested
